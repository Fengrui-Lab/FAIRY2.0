# Lifecycle knowledge

`lifecycle.py` provides a closed schema, source bundle, offline LLM extraction and validation. Phase knowledge gives goals, public observations, allowed operations and evidence predicates, not an executable fixed-date Oracle. Workflow phase and observed biological stage are separate.

The five phases are preparation, establishment, growth management, harvest and postharvest. Every knowledge file is scoped to its declared soybean cultivar and backend public evidence and the actual public tool-contract fingerprint, with local code source hashes. Manual Oracle code is coverage evidence, not an optimal answer or mandatory dosing schedule. Generated text cannot install executable predicates or unregistered tools.

`soybean_hn58.yaml` is the versioned offline extraction result when populated. Review status is machine-checked, never falsely marked human-approved. Runtime execution loads the frozen file; it does not call a model to rebuild knowledge each turn. `seed_knowledge` is a schema/reference fixture for extraction and tests, distinct from the generated runtime asset.

The packaged YAML is now the actual adopted offline model extraction. Its operation lists are non-exhaustive domain cues, not a scripted execution chain. Provenance hashes and closed completion-predicate IDs are attached by the program, not generated or repaired by the LLM. Earlier copied-example and rejected malformed extraction attempts remain in local experiment evidence.

## 0.8.0 contract rebinding

The Native YAML retains the earlier model-extracted phase text; its source hashes
and public-contract fingerprint were explicitly rebound after the common season
contract changed. `soybean_hn58.provenance.json` is retained as the historical
extraction request/response record, not a claim that the revised bindings were
newly generated by that model. Current runs record the actual loaded knowledge
fingerprint and validate its source bindings. WOFOST defaults to program-built
proxy-scoped lifecycle cards (`seed_knowledge`), not a claimed LLM extraction;
`oracle extract --backend wofost --scenario soybean_l3_901_proxy_normal_v1` can
produce a separately attributed extraction. Knowledge files and memories from
different cultivar/backend scopes are not interchangeable.
