CSV 可按 `level`、`family`、`themes` 筛选。先看 `proposed_anchor`（迁移建议）、`disturbance`（原版天气/病虫定义或母场景继承）、`initial_or_resource_rules`（初态、预算、分区和设施），再看 `migration` 和 `gaps`。有 L3 母场景的条目读取实际 checkpoint 日期和逐垄阶段计数，可以用 `parent_l3` 回查该全季扰动。旧独立短场景没有同等快照时，记录源码设置的初始阶段；收获后的任务以库存状态为准。空字段表示未静态提取到独立声明，不等于不存在过程或约束。

CSV 的可定义性和缺口是按源码声明生成的**初筛**，不同于逐场景动态验收。原版同一日期可能跨多个区的生育阶段；不要把天气日期、暴发相对日、Oracle 的参考操作窗口以及实际快照阶段当作同一种锚点。尤其 1700 及以后系列共用一组为原作业计划打开的天气窗；移植应把这些窗当作外生输入或实验变体，不能把原 Oracle 路径作为生成场景唯一合格解。糖研院试验行用于重放和标定对照；若改采样天气或管理，属于新生成样本，不能沿用原实测对照身份。

复现全量表（从仓库根目录执行，第二个参数为本地输出文件）：

```bash
python3 experimental/demo/audit_legacy_soybean_inventory.py \
  FAIRY-test_Knowledge experimental/evaluate/scenarios/LEGACY_SOYBEAN_SCENARIO_INVENTORY.csv
```

这里的“可定义”指能从标准生长与管理流程、外界扰动和任务切片重建决策问题。即使能定义，也可能缺少 2.0 的引擎能力。“仅用阶段扰动”指把事件挂在播前、出苗、开花、灌浆或成熟锚点上，而不额外引入装备故障、库存约束或前序操作的隐藏状态。

## 建议的场景生成合同

- **基线**：作物与品种、空间分区、正常气象、设施能力、预算和管理起点。首轮可借黑农84旱斑的任务结构，用已接入的黑农58做新样本；登记为 2.0 派生场景，不能宣称与原版黑农84数值等价。
- **扰动**：将天气、病虫等外生过程，与初始状态/资源约束、作业触发故障分开。每个声明记录作用垄、时间锚、持续期、强度和组合规则。一次区域性降雨用同一业务日期；分区阶段错位时分别记录作物暴露，不对每个区重播同一场雨。首轮建议从正常参考轨迹冻结事件日期，再记录实际执行触发时的阶段；只有明确要模拟“随作物阶段发生”的机制才用动态阶段锚点。
- **任务层级**：同一生成器产出完整 L3；L2 从尚须判断或等待的窗口开始，L1 从行动就绪开始。通过新版公开操作前缀制造状态、保存并校验新版快照。旧 checkpoint 用于理解原态，不注入新版私有字段；同一个历史锚点可以有多个不同任务，也可能没有独立任务。
- **自动参考轨迹**：先用确定性规则或有限搜索自动找一条合法路径，再严格回放，确认终点满足明确指标。特权轨迹只证明模拟器里存在可行路径；若要支持“智能体可解决”，还须用仅公开观测的策略重新求解，并检查诊断信号足以区分关键分支。记录搜索预算、可见证据、作用区、动作、资源和未满足条件。搜索未找到解时暂不入库，但不能反推数学不可解；找到一条也不代表最优。
- **筛掉退化样本**：有扰动无观测差异、对照已轻松满足目标而任务要求干预、不同目标区无法凭公开证据区分、经验证不具备解决动作，均不可当作有效难例。对照至少包括不干预和参考干预；资源类再加错误分批，生物类再加过早/错区处置。阶段、剂量、目标不由旧脚本签名决定，保留所有通过判据的替代轨迹。

建议下一轮先落地两条家族：**双旱斑**验证分区、额度与诊断到执行的切片，**容量分批**检验生成器是否能容纳非生物事件。等已有场景自动生成、公开可解、重放及对照门槛稳定后，再补冷春土温/出苗，并逐个接入病害和虫害。

## 本地源码查验路径

在原版快照的 `fairy/scenarios/farm_world_fullseason_v2/` 下，L3 包装文件 `scenario_full_season_*.py` 委托 `harbin_l3_batch_catalog.py` 和 `harbin_l3_batch_scenario.py`；天气、暴发配置在 `fairy/physics/profiles.py`。L2/L1 位于 `l2_l1_splits/<家族>/`；checkpoint 贯穿构造与任务起点，`l3-to-l2-l1-split-guide.zh.md` 只用于理解原版方法。上述候选及参数通过固定提交中的这些源码核查，无需运行时依赖原仓库。
