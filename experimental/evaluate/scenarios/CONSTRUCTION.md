# HEINONG58 normal 与干旱组合：首轮构建合同

本文保留0.6.0 Native场景构建合同；0.8.0新增的WOFOST代理、粗阶段日历与验收见[接入说明](../../demo/WOFOST_FULL_SEASON.md)，不将本文R1/R5日历冒充WOFOST分期。

历史版本：FAIRY 0.6.0，Runtime schema 6。实现位于仓库的 `experimental/`，洪涝和虫害未接入。

## 基线、模板、策略分别定义

`normal.py` 定义正常环境与标准管理知识模板；`lib/l3/soybean_normal.py` 声明具体初态、资源和入口。
模板描述播前准备、建植、营养生长、开花结荚、鼓粒、收获及安全储藏的目标、观测和可选操作。
它不是必须照抄的工具链，也不会让运行时替智能体执行操作；当前不会自动作为RAG知识注入模型。

本轮只覆盖已有水分、简化生长、装备作业和粮食物料过程，没有声称实现全部养分、病虫草管理。
历史黑农84 normal 未复制或换名作为黑农58模型；本轮是HEINONG58简化代理的新合成基线。

正常输入为64垄、每垄268 m、垄距1.1 m、株距7.9 cm、播深40 mm；根区初始含水率为田间持水量0.31。
逐日最低/最高温度16/28°C、太阳辐射18 MJ/m²、降雨3 mm、ET0 3 mm、风速2 m/s、水汽压12 hPa。
这些常量是理想化工程输入，不是哈尔滨站点实测天气或田间校准结果。正常供水不等于无限资源。
所有变体采用相同种子、燃油、容量及60 mm全田等效灌溉额度，初态均未播种。

## 入口及唯一变化因素

| 场景ID | 相对normal的变化 |
| --- | --- |
| `soybean_l3_hn58_normal_v1` | 无附加扰动 |
| `soybean_l3_hn58_drought_r1_v1` | R1参考窗口12天降雨置零 |
| `soybean_l3_hn58_drought_r5_v1` | R5参考窗口10天降雨置零 |
| `soybean_l3_hn58_drought_r1_r5_v1` | 两个窗口组合 |

保留两个单扰动用于与组合对照。四个场景公开任务文本完全相同；没有换初态、额度或注入处理答案。
未来计划仅进入受保护的构建元数据，不进入默认模型上下文。天气服务仍提供其声明范围内的公开预报。

## 声明、编译和运行

1. `Drought` 声明唯一ID、阶段、日偏移、持续天数、降雨比例和目标。
2. `compose.py` 读取冻结normal参考日历，将阶段锚点解析成固定日期，不创建引擎。
3. 校验来源、初态、模板、模型过程源文件及时间窗口；重叠的同日降雨修改明确拒绝，不依赖配置顺序。
4. 编译完整逐日天气，保存normal、配方、参考日历及最终天气指纹。
5. Runtime沿用唯一时钟和日步进，土壤与作物响应仍归生物后端所有。

唯一支持的扰动是整块地的 `rainfall_deficit`，比例在[0,1)，不改变其他天气字段。
不支持局部降雨、实际阶段动态触发、洪涝、虫害或任意内部状态补丁；相关声明明确拒绝。
扰动不直接扣除产量或设置损失分。事件结束只恢复降雨，不重置土壤亏缺及此前生长影响。

## 事件、观测和恢复

首轮扰动已编译进不可变逐日输入，不增加另一套动态调度器或作物时钟。
每个 `environment_day_completed` 记录构建指纹和该日实际生效的扰动ID；正常日列表为空。
这些是审计事实，不是向Agent自动宣布隐藏诊断的报警，公开工具不泄漏未来日历。

快照保存构建元数据、冻结天气和后端日游标。恢复验证配方是否真正生成了持久化天气，
核对每日输入审计，再继续已有日步进；不重做normal参考、不按候选作物阶段重排事件，也不调用LLM。
重复读取和分段推进不重复应用扰动或结算灌溉。

状态schema升至6，版本升至0.6.0；旧产物保留inspect，不改版本号伪装兼容。
WOFOST全季仍明确不支持，原Native/WOFOST的L1能力保持，不静默切换后端。

## 对照与复现

在仓库根运行，输出目录必须尚不存在：

```bash
.venv/bin/python -m evaluate.experiments.validation.normal --out .runs/normal-suite-new
.venv/bin/python -m interface.cli run --scenario soybean_l3_hn58_normal_v1
.venv/bin/python -m interface.cli run --scenario soybean_l3_hn58_drought_r1_r5_v1
.venv/bin/python -m pytest -q --disable-warnings
```

验收输出七条完整产物：normal无额外补水；三个扰动场景各自无补水/固定补水。
固定补水是每个事件中点20 mm整田灌溉，单扰动20 mm、双扰动40 mm，均不超过共同的60 mm额度。
这是因果验证策略，不是最优剂量，不写入默认任务或运行时。

验证正常收储、阶段覆盖、实际公开含水率下降、无补水相对normal的差异、相同输入下固定补水的
正向实际入库干物质响应、水量与物料守恒，以及全部轨迹严格回放。组合影响由过程产生，不线性叠加。
不引入FOS、潜在生物产量或历史流程综合分；工程闭环通过也不代表真实田间效果。

维护者显式重建命令（有意替换包内参考文件，不是普通运行步骤）：

```bash
.venv/bin/python -m evaluate.experiments.validation.normal --build-reference
```
