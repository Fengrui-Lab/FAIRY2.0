# 监督诊断、LLM 操作决策与数值剂量策略

FAIRY 的目标是让监督诊断专家从公开观测提炼作物状态，让 LLM 决定操作、目标和时机，再由数值策略为已选操作定量。现有全季 PPO 将补水时机和剂量交给同一策略，可作为历史对照。

| 组件 | 输入 | 输出 |
| --- | --- | --- |
| 监督诊断专家 | 公开墒情、分区土壤参数、作物阶段和作业回执。训练标签来自 WOFOST 内部的水分胁迫状态。 | 带日期、范围和证据状态的诊断，必要时给出分区排序。 |
| LLM | 任务、可用操作、关键诊断和回执。 | 用 `request_irrigation(start_ridge, end_ridge)` 选择目标并请求现在补水，或选择其他操作。 |
| 剂量策略 | 所选范围的公开逐垄墒情、阶段、土壤水分上下界，上次结算剂量、已发布气象（如有）和允许的最大毛水深。 | 有效的正剂量（局部 mm），或明确弃权。 |
| Controller / Runtime | 已校验的剂量和原目标。 | 一条普通 `irrigate_range` 操作及回执，待水量在本地午夜结算。 |

`request_irrigation` 是模型侧意图。委派模式从模型工具清单移除直接传剂量的灌溉入口。目标范围有同日作物和土壤证据、作物已出苗、目标无待结算灌溉且可执行剂量为正时，controller 才调用剂量策略。证据无效、重复提交或剂量弃权会返回明确反馈，并计入执行错误预算。已选剂量、证据指纹和实际事件编号写入运行产物。严格回放只使用记录里的物理操作，恢复会重建公开观测证据。

## 执行验证

首个接入点是 WOFOST Soybean_901 运行的 LLM 路径。使用 `--fixed-irrigation-dose-mm 8` 开启固定剂量集成对照。它按设备和场景的现有合法范围给出剂量，便于独立验证执行协议。恢复时指定相同参数。用真实 LLM 运行时沿用现有服务配置。

```sh
cd experimental
python -m interface.cli run --scenario soybean_l3_901_proxy_normal_v1 \
  --backend wofost --agent llm --fixed-irrigation-dose-mm 8 --out .runs/dose-example.json
python -m interface.cli replay .runs/dose-example.json
python -m pytest demo/test_irrigation_dosing.py -q
```

## 首轮训练范围

按确认采用常规管理条件。首轮实验不沿用全田 PPO 试验额外设定的 60 mm 水额或节水惩罚。剂量执行遵循农场实际和引擎的基本边界。训练回放真实 LLM 的请求，由原请求固定时间和目标分区。已有干旱及专家消融日志包含重复前缀和同一情景的多次采样，复用时须按请求前状态分组去重。新增采集优先覆盖常规管理的多个年份、地块和生育阶段；按年份和场景留出，将剂量比较与全闭环评估分开。剂量表达、奖励和结算后的评估窗口在训练前交互确认。训练确认前，执行链用显式固定策略提供可复现的对照。施肥接入依赖经验证的营养状态标签和施肥响应。
