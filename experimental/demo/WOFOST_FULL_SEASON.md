# WOFOST 全季与自动 Oracle 接入验收

当前实现版本：FAIRY 0.8.1、Runtime schema 7、数值策略 schema 2／特征版本 2。
日期：2026-11-16。旧产物保留查看，不通过修改版本字段伪装兼容。

## 实现范围

全季生物契约增加类型化 `RidgeStatus`，运行时、物理装备、评价和手工参考策略不再读取
Native 的逐垄内部字典。公共作物观测增加粗粒度 `phase` 与 `harvestable`，保留 Native
原细分分期；WOFOST 不把 DVS 冒充 R1—R8。

现有离线 PCSE 6.0.13／WOFOST 8.1 水分限制模型扩展到64个独立列。实际播种保留播前
土壤历史，分区水量在统一日界结算，成熟干物质移交给原装备回收、烘干和入库账本。
既有 L1 入口不改为全季模式。运行时不导入历史 reference 实现。

| 场景 | 用途 |
| --- | --- |
| `soybean_l3_901_proxy_normal_v1` | 与现有 normal 相同几何和外部正常天气的工程代理 |
| `soybean_l3_901_proxy_calendar_drought_v1` | 采用原 Native 参考的固定干旱日期；不宣称覆盖 WOFOST R1/R5 |
| `soybean_l3_901_proxy_reproductive_drought_v1` | 从冻结 WOFOST normal 粗阶段日历编译的40天生殖期降雨缺失 |

同一场景的控制和管理组使用完全相同天气。参考日历经公开操作离线构建；候选策略
不会触发重新排期。正常参考粗阶段为5月5日出苗前、5月10日营养期、6月3日生殖期、
7月30日成熟；这些是当前代理模型结果，不是黑农58田间观测。

## 自动 Oracle

保留 LLM 决定全部公开操作、知识提供流程依据、MaskablePPO 仅提供全田剂量建议的分工。
数值训练和真实候选通过同一 Runtime 及工具执行。训练 driver 明确单独标识，不冒充
真实 LLM。剂量仍为0／5／10／20／30 mm，水额由运行时硬约束。

特征使用公开粗阶段、水分、已发布天气及水额；终局奖励使用安全入库干质量与事先
声明的水成本，不使用逐日 WSO 存量奖励。策略清单绑定后端、品种、参数来源、源码、
特征版本、场景范围及权重哈希；旧策略必须重新训练。不同后端、场景、源码或目标的
候选按比较域分别选择，不生成跨域总冠军。

训练中的固定收储驱动按批次卸粮并处理入库，避免WOFOST较大收获量挤爆拖车。晚熟、
超时及交付失败产生明确失败反馈，不无限等待或静默丢弃。

## 审阅修复

- 修复成熟事件在延迟速率计算下多保留一天冠层的问题：成熟积分边界立即完成作物
  清理，后续裸地蒸腾为零。独立复核成熟干物质不变，日水量守恒。
- 恢复采用固定初始化与输入重建，核对公开操作对应的播种、补水和收获日志；拒绝
  改写摘要、错位天气、重复灌溉和非法分区。
- 后端恢复比较保持在ACPS内部，不反向导入运行时或评价模块。
- 资格认定核对策略manifest与建议轨迹实际使用的策略指纹。

## 边界

Soybean_901 参数来自已固定哈希的上游大豆文件，原描述为法国北部参数化。
本轮没有黑农58校准，没有验证田间产量、实际仪器精度或密度响应。籽粒含水率及
合成传感器是明确记录的工程代理，未加入病虫害、倒伏或垄间水分交换。

恢复是 O(分区数×历史长度) 的重建；64列真实训练成本高于 Native。训练权重更新
不代表优于零灌溉或固定规则，也不证明全局最优。工程闭环、因果验证与真实 LLM
结果分别列证据，未完成的环节不得写成通过。

## 0.8.1 长程验收后补修

新增回归在Native与WOFOST上均复现：部分垄已收获、其余垄成熟时，重新读取作物后，
旧工作流将已收获垄当成未成熟对象，误退回growth_management。现按成功收获回执过滤
已完成垄，再判断剩余对象是否可收获，不改变作物实际状态或工具执行条件。

为降低有限历史中的重复容量试探，公开上下文增加`public_containers`和
`latest_harvest_receipt`。库存读取校准已知量，后续成功收获／卸粮／干燥／入库回执
更新存量；没有依据的数量保持null。没有从物理后端免费读取隐藏库存，也没有预测
未收获产量或强制执行固定工具序列。独立评审复核投影与实际账本一致；修改隐藏库存
而不产生公开回执时，投影不会变化。

0.8.0原始产物及匹配轮包完整保留。0.8.1使用新源码指纹、新训练权重及全新真实LLM
运行，不改写旧状态版本和指纹。最终0.8.1测试与真实运行结果在本节补充。
