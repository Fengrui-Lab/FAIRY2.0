## 关键行为

### 中断与恢复

一次作业仍是串行原子操作。可捕获中断时撤销整次未完成操作，而不是从装备作业中途继续。取消意图保留在事件中，但没有物理效果；严格回放重建取消记录，不再执行被取消操作。

`run_suspended` 不清除历史，也不把任务标为成功或永久终止。`resume INPUT --out NEW_OUTPUT` 使用新实例恢复，再由指定策略继续。done=true 的正常终止或预算耗尽产物不能通过改标志续跑。

SIGKILL、掉电和连续中断保存过程不在该保证内；本轮没有声称支持这些故障的持久检查点。

### 公开上下文与停滞

模型仍只得到公开信息。最近观测最多保留12个目标，未解除拒绝最多8条；完整回执带记录时间，不将旧观测伪装成当前事实。整条预算淘汰会明确记录遗漏数。不能仅凭后续任意成功动作就清除旧错误。

低进展是可审计诊断，不是农艺正确性的裁决；它不会强制推进时间、禁止正常复查或给模型 Oracle 日程。是否改善真实模型全季策略仍需另做真实实验，不能由此声称所有模型均能完成。

### 模型协议与累计用量

协议错误与业务拒绝独立。`--max-protocol-errors` 默认3；`--max-errors` 控制实际工具拒绝。非法模型响应不产生 `operation_requested`，也不伪造一个物理工具调用。协议反馈是公开的稳定原因码，不携带服务异常正文。

每次调用保存脱敏指纹、规范逻辑请求字符/字节、finish_reason、原始/有效调用数、模型返回名称（服务未返回时标未知）及服务 token 用量。字节值不是 SDK 实际 wire 字节，也不是 token 估算；凭证不在这些负载中。续跑记录本段用量及此前累计用量，并引用原产物指纹；SDK传输重试仍关闭。

`soybean_l3_hn58_waterlimit_v1` 的原始 `weather.json` 没有改动。当前 `soybean_full_season()` 对应 `soybean_l3_hn58_waterlimit_v2`，使用派生的 `weather_v2.json`。

### 执行身份和产物

Runtime schema 5 在状态中保存执行内容指纹；环境清单保存 `fairy/evaluate/interface` 包内 `.py/.json/.yaml` 的逐文件哈希。恢复与严格回放要求实际包内容匹配，不仅比手写版本号。该机制适用于源码与解包 wheel；不是文件签名，也不防恶意篡改全部证据。

CLI 默认生成唯一输出名称；显式路径及对应进度文件必须尚不存在。正式产物原子发布且不覆盖；同一路径并发写入仅一个成功。程序化 `write_json(..., overwrite=True)` 是显式开发快照选项，CLI 不开放它。

旧 schema 4 仅可 inspect，不改版本号冒充 schema 5。手动修改源码会改变执行指纹，已有状态需要保留原执行环境才能恢复；这属于有意的兼容性边界。
